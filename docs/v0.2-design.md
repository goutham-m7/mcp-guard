# v0.2 technical design

## Problem and constraints
Extend the existing default-deny trust boundary without pretending heuristic scanning is complete. Local-only work, original synthetic data, standard-library-first additions, existing transports and CLI conventions. No employer assets or external services.

## Chosen design and alternatives
Policy keeps conjunctive rules. Optional `servers`, `resources`, and `prompts` sections reuse the tool rule schema. A leaf grant is mandatory; matching server rules only narrow it. Server rates use one shared bucket; leaf rates use per-operation identity. Override/merge-last policies were rejected because an accidental specific grant could widen a global restriction.

Resource identifiers use `mcp-guard://SERVER/` plus percent-encoded original URI; prompts use existing `SERVER__NAME` convention. Decode only by lookup in a freshly pinned inventory, never by trusting client routing. Refresh only the requested surface; advertise resources/prompts only when configured. Resource templates, subscriptions and server-initiated sampling stay unsupported. Binary output remains unscannable and blocked. Prompt/resource metadata and returned messages pass existing scanning, with separate surface pin keys. Tool-only configuration remains compatible.

Evaluation retains the original 40 tuning fixtures. A separate synthetic holdout is committed before it is measured. No detector tuning after inspection of holdout results. This is not an independently authored or real-world benchmark. A separate benign set intentionally includes expected conservative false positives. Reports retain misses, errors, category counts and per-detector benign hit denominators.

Audit JSONL gets `schema_version: 1`; existing fields remain stable and contain no payload. Query validates every line before filtering; malformed input fails with a line number, not content. No OpenTelemetry dependency or collector.

Benchmark workers each own a real benign stdio server and Guard. Warm initialization/discovery excluded; each timed tools/call still refreshes discovery and writes audit. Calls serialize per session; independent sessions run concurrently. Collect nearest-rank percentiles, wall-clock throughput and errors. This is end-to-end local call latency, not incremental proxy overhead.

## Interfaces and data flow
CLI -> Policy/Guard -> existing upstream adapters -> detector -> audit -> result. New `policy check`, `audit query`, `benchmark` commands stay offline except local subprocesses. Packaged fixtures and audit schema use importlib.resources. Wheel/sdist built with existing uv backend.

## Failure and security behavior
Unknown leaf operations denied. Any matching deny wins. Input shape errors fail before execution. Metadata changes quarantine for session lifetime. Unsupported/binary content is denied, never rewritten. Sampling remains disabled at transport boundary. Audit errors remain fail-closed. Rate limits and pins are session-local; read operations can still have upstream side effects and no rollback exists.

## Rollout and verification
Eight independently committed roadmap items. Existing tool policies need no migration; newly optional sections opt in surfaces. Audit consumers may ignore the added version field. Version metadata moves to 0.2.0 only for release build. Unit tests cover policy/report math; CLI tests cover errors; real subprocess journeys cover protocol and benchmark. A fresh local clone must install, pass full tests/lint/format, demo, replay, benchmark and build; installed wheel must load packaged data. No hosted CI claim.
